## 1. 배경

### 1.1 현행(#0001) 한계
#0001은 RAW 4개를 **한 번에 업로드 → 즉시 전체 처리**하는 전제다. 실제 현장은 SAP에서 문서를 **순차 생성**하며 4개 RAW가 동시에 존재하지 않는다.

### 1.2 작업자 실제 동선 (검증 완료, 부록 C)
"이전 문서에서 컬럼 복사 → SAP 티코드 붙여넣기 → 새 문서 생성·다운로드"의 반복. 데이터 계보 실측 100% 검증(부록 C).

### 1.3 핵심 데이터 사실 (코드·실측 확인)
- **자재코드**가 1·3·4단계를 잇는 마스터 키 (170/170).
- **2단계(물류분배)는 앱 데이터 파이프라인에 미참여** — `processJob`은 stage1·3·4만 받고 `resolveStage2`조차 없음. 2단계는 **작업자 동선 안내 + 통합엑셀 RAW 시트 보존용**으로만 존재.
- **출력1은 1단계만으로 생성 가능** (`generateOutput1`은 stage1 단독; PG는 나중에 머지하는 빈칸).
- 출력2·3은 1+3+4단계 필요.

### 1.4 목표
앱 화면 단계를 작업자 SAP 작업 순서와 1:1 일치시키고, 각 단계에서 **다음 SAP 작업에 붙여넣을 컬럼을 복사 버튼**으로 제공한다.

## 2. 목표 / 비목표

### 2.1 목표
- **G1.** RAW 업로드를 단계별로 분리, 화면을 SAP 순서(STEP 1~8)와 일치.
- **G2.** 각 단계에서 다음 티코드 입력 컬럼을 **"전체 복사" 버튼**으로 제공.
- **G3.** 변환 **규칙**(소스빈 분리·브랜드 정제·그룹SUM·페이지 분할·EAN 매칭)은 #0001 함수를 그대로 호출. **단, 잡 store·processJob·라우트는 재설계** (부록 B).
- **G4.** 잡은 단계 상태(`step`)를 가지며 중간 이탈/재진입 시 복원.
- **G5.** 출력1은 STEP1 직후 본문 생성(합계 검증)·STEP4에서 PG만 머지. 출력2·3은 STEP6 이후 생성.

### 2.2 비목표
- **N1.** SAP 자동 연동 (수동 복사·붙여넣기·다운로드 유지).
- **N2.** 변환 **규칙** 변경 (#0001 유지).
- **N3.** **통합 4시트 동시 업로드 경로는 프로덕션 비활성** — 인증된 개발자 플래그(`ENABLE_BULK_UPLOAD`) 뒤에서만 노출. 운영 노출 시 단계 가드 우회 위험.
- **N4.** 브랜드 통합 매핑(LF종합관) — 현행 괄호제거 유지 (Q3 최종검증).

## 4. 요구사항

### 4.0 F0 — 단계별 업로드 공통 검증 (#0001 F11 상속)
- **모든** 단계 업로드(STEP 1/2/5/6)는 #0001 F11 검증을 **동일 적용**: `.xlsx`만, magic byte `PK\x03\x04`, `[Content_Types].xml` 존재, `.xlsm`/외부링크 거부, 단일 50MB·누적 100MB 상한, 시트당 5만행(ref 사전검사) ZIP bomb 가드.
- **F0.1 단계 판별은 시트명·파일명이 아니라 컬럼(헤더)으로만 한다** (★실측 수정). SAP 단일단계 RAW 내보내기는 시트명이 거의 항상 `Sheet1`이므로, 시트명 기반 사전 탈락(`/^sheet\d*$/i`, `/^티코드$/`)을 제거한다. 워크북의 **모든 시트를 파싱**하고, 헤더 행(비어있지 않은 셀 ≥5)이 없는 시트만 자동 제외한다. 단계 매핑은 `detectStage`(헤더 시그니처) 결과로만 결정 — 어떤 시트명이든 컬럼이 맞으면 인식, 안 맞으면(stage=null) 선택되지 않는다. #0001 F1.4의 "티코드 시트 무시"는 시트명이 아니라 "컬럼 미매칭 → 미선택"으로 자연 달성된다.
- **모든 신규 라우트**는 #0001 인증 세션 검증 대상, 미인증 401/리다이렉트.
- **레이트리밋**: 단계 업로드 IP당 분당 5회, 단계전이/복사추출/PG입력 분당 30회.
- **소유권**: 모든 잡 단계 라우트(업로드·추출·PG·전이·다운로드)에 `checkJobOwnership` — 타 소유자 404. (복사용 추출 엔드포인트 미적용 시 자재코드 170건 IDOR 유출)

### 4.1 F1 — 잡 생애주기 재설계 (★must-fix #1)
> #0001 store는 "stage1·3·4 동시 + status=ready 하드코딩"이라 부분 저장 불가. 아래로 재설계.

- **신규 `step` 컬럼** (jobs 테이블). 기존 `status` enum은 **`step`으로 대체**(폐기). 진실의 원천 = `step` 단일 축.
- step 값: `s1_uploaded` → `pg_entered` → `s3_uploaded` → `s4_uploaded` → `ready`
  - **`s2_uploaded`는 선택 노드** — `s1_uploaded → {pg_entered | s2_uploaded → pg_entered}` 둘 다 합법.
- **INSERT 시점**: STEP1 업로드 직후 **부분 레코드 생성**(stage1만 보유, step=`s1_uploaded`, 소유자=현재 이메일). ready 전이는 출력2·3 생성 가능 시점.
- **누적 저장**: Blob 페이로드를 단계별 부분 채움. `rawSheets.stageN`을 단계마다 누적. (store의 `CreateJobInput`/`JobRecord`/`JobPatch`/`createJob`/`updateJob` **구조 변경 필요** — stage1/3/4 non-null 강제 해제, stage는 단계별 nullable 누적)
- **전이 가드** `canTransition(from, to)`: 합법 전이 매트릭스(부록 D)로 강제. 불법 전이는 서버에서 거부(409).
- **동시성**: step 전이는 낙관적 동시성 `UPDATE ... SET step=$new WHERE id=$id AND step=$expected`. rowCount=0이면 409(다른 탭이 이미 전이). (pgNumbers/headerOverrides는 #0001 jsonb LWW 유지)
- **재진입 복원**: GET 응답에 `step` 포함. step→화면 매핑 + **'step이 요구하는 데이터 존재' 검증**. 불일치 시 복구 가능한 마지막 step으로 강등. (getJob이 부분 잡에 404 내지 않도록 수정 — blob/data 부분 허용)

### 4.2 F2 — STEP1: 1단계 업로드 + 컬럼 추출 + 출력1 본문
- 1단계 시그니처 검증 → 잡 부분 생성(step=s1_uploaded).
- **신규 추출 모듈** `lib/extract`: 컬럼 **distinct** 추출(셀 단위, 행 스킵 아님). `resolveStage1`에 **분배번호(M열) 인덱스 신규 추가** (현재 없음).
  - 분배번호(M): distinct (실측 2종) — dedup 고정
  - 자재(S): distinct (170종)
- **추출값은 원본 문자열 보존** — 숫자 변환 금지(선행 0/지수표기/소수점 오염 방지), `trim`만.
- **출력1 본문 생성**(generateOutput1, stage1 단독) + 합계 검증(=1단계 합계). PG는 빈칸.

### 4.3 F3 — STEP2: 2단계 업로드 (선택, 데이터 미참여)
- 2단계 시그니처 검증 → RAW 보존용으로만 Blob 저장(통합엑셀 시트용). **앱 변환에 미사용**.
- 납품번호/분배번호 1단계 교차검증(경고만).
- 사용자가 **건너뛰기 가능**(s1→pg 직행 합법).

### 4.4 F4 — STEP3: PG 입력 + 분배번호 복사
- **분배번호 복사 버튼**(STEP1 동일값) — PG생성 티코드용.
- **PG 입력**: `^\d{10}$`, 플랜트당 1개(#0001 F7 규칙). 통과 시 전이 `→ pg_entered`(전용 라우트 + 가드).

### 4.5 F5 — STEP4: 출력1 미리보기 + PG 복사
- 출력1 본문(STEP1 생성분) + **PG번호 머지** 미리보기.
- **PG번호 복사 버튼** — 피킹지시서 티코드용.

### 4.6 F6 — STEP5: 3단계 업로드 + 자재코드 복사
- 3단계 시그니처 검증 → 누적 저장, 전이 `→ s3_uploaded`.
- **자재코드(E열) 복사 버튼**(distinct 170종) — EAN 조회 티코드용.
- 소스빈 분리 미리보기 + ETC(E·G~Z) 카운트 경고.

### 4.7 F7 — STEP6: 4단계 업로드
- 4단계 시그니처 검증 → 누적 저장, 전이 `→ s4_uploaded`.
- EAN 다중매칭 #0001 규칙(EAN==상품코드 우선, 없으면 첫 행 — Q4 최종검증).

### 4.8 F8 — STEP7~8: 출력2·3 + 인쇄/다운로드
- **processJob 분해**(★must-fix #2): `processOutput1(stage1, pg)` 와 `processOutputs23(stage1, stage3, stage4)` 두 경로로 분리. STEP7에서 후자 실행 → 전이 `→ ready`. outletName/detectedPlants는 출력1(stage1)에서 채움.
- ETC 0건 아니면 확인 체크박스 강제(#0001 유지).
- 인쇄 미리보기(머리글/바닥글 인라인 편집) + 통합 엑셀(RAW1~4 + 출력1·2·3 + ETC, 8시트).

### 4.9 F9 — 복사 버튼 동작
- **개행 포맷 설정 가능**(★must-fix #6): `LF` / `CRLF` / `탭+CRLF` 중 택 (기본값은 현장 1회 검증 후 고정, 잠정 CRLF). SAP GUI 멀티플셀렉션 호환.
- `navigator.clipboard.writeText` + **fallback**: API 미존재(비보안컨텍스트)/권한거부 구분 → 읽기전용 textarea 전체선택 + "Ctrl+C 안내".
- **값 무손실**: 원본 문자열 그대로(숫자 변환 금지).
- dedup 토글: **분배번호=ON 고정(숨김)**, 자재/자재코드=기본 ON(전체행 필요 시 해제 가능 — Q2 검증).
- 성공 토스트(+항목수)/실패 토스트 각각 명세. 버튼 `aria-live` "복사됨" 상태변화.
- trailing newline 정책: 포맷 확정 시 함께 고정.

### 4.10 F10 — 진행 네비 + 무효화 전이표
- STEP 진행 표시(현재 강조/완료 체크). 뒤로가기 허용.
- **무효화 전이표**(부록 D): 뒤 단계에서 앞 RAW 재업로드 시 step 강등 + 폐기 집합 명시 + 재계산 트리거. 확인 모달 동반.

## 6. 엣지케이스

- **E2.** 잘못된 단계 파일 업로드 → 시그니처 불일치 거부.
- **E3.** 클립보드 API 미존재/권한거부 → textarea fallback + Ctrl+C 안내.
- **E4.** 앞 단계 RAW 재업로드 → 무효화 전이표(부록 D) + 모달.
- **E5.** 컬럼 추출 시 빈/공백 셀 제외 (셀 단위, 행 스킵 아님).

## 7. 성공기준

- **AC2.** STEP3 PG `^\d{10}$` 위반 시 전이 차단.
- **AC3.** **STEP1 직후** 출력1 합계 = 1단계 합계(샘플 415).
- **AC4.** STEP5 자재코드 복사 = distinct 170종.
- **AC5.** STEP7 출력2·3 + 페이지 분할 = #0001 AC(415, 페이지수, ETC) 동일.
- **AC6.** 잡 재진입 시 직전 step 화면 복원 + 데이터 완전성 검증.

## 부록 F — 단계 네비게이션 (F11 추가, 클라이언트 전용)

### F11 — 도달한 단계 간 자유 이동
PRD §5의 "뒤로가기 허용"을 실제 UI로 구현. 서버/스토어/DB 무변경.

- **요구사항**:
  - F11.1 진행 표시줄의 각 단계 라벨을 **클릭**하면 해당 단계 화면으로 이동.
  - F11.2 **이전(‹)/다음(›) 화살표** 버튼으로 단계 이동.
  - F11.3 이동 가능 범위 = **도달한 가장 먼 단계(furthest)까지**. 미도달 단계는 비활성(회색).
  - F11.4 각 화면의 **액션(업로드/PG 입력)은 서버 전이 가드를 그대로 따름** — 순서 위반 호출 시 422/409 + 토스트. UI는 순서를 막지 않되 서버가 진실의 원천.
  - F11.5 데이터가 있는 단계는 그대로 표시(복사 버튼·출력1 표). 데이터 없는(미도달) 단계 화면은 안내 문구.
- **상태 모델**: 클라이언트 `viewIdx`(보는 화면) ≠ `view.step`(서버 furthest). `viewIdx ∈ [0, furthestScreen(view.step)]`.
- **화면 인덱스 ↔ 단계**:
  | idx | 화면 | 조작 |
  |-----|------|------|
  | 0 | 1단계 결과 | 분배번호·자재 복사 + 출력1 요약 |
  | 1 | 2단계(선택) | 2단계 업로드 / PG 직행 |
  | 2 | PG 입력 | 분배번호 복사 + PG 폼 |
  | 3 | 출력1 미리보기 | 출력1 표 + PG번호 복사 |
  | 4 | 3단계 | 자재코드 복사 + 3단계 업로드 |
  | 5 | 4단계 | 4단계 업로드 |
  | 6 | 최종 | 인쇄/다운로드 |
- **furthestScreen(step)**: s1/s2→3, pg_entered→4, s3→5, s4→6, ready→6.
- **AC11.1**: 진행줄에서 도달 단계 클릭 시 그 화면이 보이고, 미도달 단계는 클릭 불가.
- **AC11.2**: 이전/다음 버튼이 [0, furthest]로 클램프.
- **AC11.3**: 도달 단계 재방문 시 해당 단계 데이터(복사/출력1)가 정상 표시.
- **비목표**: 미도달 단계로의 전진 점프(데이터·액션 모두 없음)는 허용 안 함.

### F12 — 홈 화면 인라인 호스팅 (별도 잡 화면 진입 제거)
F11의 단계 네비게이션을 **홈(`/`) 화면 그 자리에서** 쓰도록 한다. 업로드 후 `/jobs/[id]`로 라우트 이동하지 않고, 홈에서 `JobFlow`를 인라인 렌더한다. 서버/스토어/DB·API 무변경(`POST /api/jobs`가 이미 `view` 반환).

- **요구사항**:
  - F12.1 홈에서 1단계 업로드 성공 시 **라우트 이동 없이** 같은 화면에 `JobFlow`(F11 단계바·화살표 포함)를 인라인 렌더한다.
  - F12.2 잡 진행 중 홈 상단에 잡 요약(잡 #id·플랜트·만료)과 **"+ 새 작업"**(인라인 상태 초기화) 버튼을 둔다.
  - F12.3 업로드 전에는 단계바를 **클릭되는 네비처럼 노출하지 않는다**(데이터·잡 없음). 한 줄 안내만 표시.
  - F12.4 `/jobs/[id]` 라우트는 **딥링크/관리자 다운로드용으로 유지**(소유권 체크 유지). 인라인 경로는 업로더 본인에게 API가 반환한 `view`만 사용 → **신규 데이터 노출 없음**.
  - F12.5 브라우저 하드 리프레시 시 인라인 잡 상태는 소실되며(클라이언트 상태), 잡은 서버에 보존되어 `/jobs/[id]`·관리 페이지로 접근 가능. (URL 동기화는 비목표.)
- **상태 모델**: 홈 클라이언트 래퍼 `HomeFlow`가 `view: JobView | null` 보유. null→안내+업로드, 값→`JobFlow` 인라인.
- **AC12.1**: 홈에서 업로드하면 URL이 `/`에 머문 채 단계바·화살표가 즉시 나타나고 단계 이동이 동작한다.
- **AC12.2**: "+ 새 작업" 클릭 시 업로드 화면으로 복귀한다.
- **AC12.3**: 비인증 사용자의 업로드 호출은 종전대로 401(미들웨어). 인라인 경로가 타인 잡을 노출하지 않는다.

### F13 — 업로드 실패 진단·견고화 (★실측 수정)
파싱 통과 후 잡 생성(`createJobAtStep1`) 단계 예외가 라우트에 try/catch 없이 그대로 500이 되어, 클라이언트가 `업로드 실패: `(빈 메시지)만 보였다. 또한 실데이터 업로드가 그간 파서에서 막혀(Sheet1) DB insert 경로가 처음 실행되며 잠복 문제가 드러남.

- **F13.1** `POST /api/jobs`는 잡 생성 예외를 try/catch로 잡아 서버 로그(`console.error`)에 상세를 남기고, 클라이언트엔 안정적 코드 `job_create_failed`(빈 메시지 금지)만 반환한다. 내부 메시지/스택은 사용자에게 노출하지 않는다(에러 누출 방지).
- **F13.2 FK 자가복구**: `jobs.plnt → plants.plnt` FK 때문에 plants에 해당 plnt 행이 없으면 insert가 실패한다. 잡 생성 시 plants 행을 `onConflictDoNothing`으로 먼저 보장(부트스트랩 시드 누락/신규 플랜트 대비).
- **F13.3 진단 라우트**: `GET /api/admin/db-introspect`(Bearer CRON_SECRET)가 `jobs` 컬럼 목록과 누락 컬럼(특히 `step`, 마이그레이션 0002)을 함께 반환한다.
- **운영 전제**: 모든 마이그레이션(0000~0003) 적용 필요. `step` 컬럼(0002) 또는 plants 시드(0000)가 누락된 운영 DB는 `npm run db:migrate`로 멱등 적용.
