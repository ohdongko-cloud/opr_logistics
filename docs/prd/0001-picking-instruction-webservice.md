## 1. 배경
- 강서점(plnt **8227**)을 시작으로 운영팀이 SAP에서 출력한 RAW 엑셀 4종(`1단계(STO)`, `2단계(물류분배)`, `3단계(피킹지시서패션)`, `4단계(EAN)`)을 수동으로 분류·재정렬해 A4 피킹지시서를 인쇄해 왔다.
- 기존엔 엑셀 VBA 매크로로 일부 자동화했으나, 작업 단위가 **복종 × 아이템 × 소스빈 그룹**별로 잘게 쪼개져 매번 손이 많이 들고 누락·중복·머리글 깨짐(반복 머리글 무시되는 버그 등)이 잦았다.
- 이를 웹서비스로 옮겨, (a) 4개 RAW 자동 업로드/판별 → (b) 출력1·2·3 자동 생성 → (c) 복종×아이템×그룹(ABC/DF)별 A4 페이지 자동 분할 → (d) 인쇄 미리보기/통합 엑셀 다운로드까지 끝낸다.
- **사용자 규모**: 동시 3~5명 (장기 10명 이하). 내부 운영팀 한정.

## 2. 목표 / 비목표

### 2.1 목표
- **G1.** 4개 RAW 파일을 **파일명/시트명 무관**하게 **컬럼 헤더 시그니처**로 자동 판별해 처리한다 (실패 시 수동 지정).
- **G2.** 사용자가 **PG번호**를 출력 직전에 직접 입력하고, **플랜트별 PG 일관성 위반 시 즉시 차단**한다.
- **G3.** 출력1·2·3 시트 양식을 **그대로 보존**하고 컬럼 순서·헤더를 변경하지 않는다.
- **G4.** **복종(W/M) × 아이템(자재그룹 우 2글자) × 그룹(ABC/DF, E·기타는 ETC 리포트)** 조합으로 A4 한 페이지씩 인쇄한다.
- **G5.** 작업 완료 후, 4 RAW + 출력1·2·3 + ETC 리포트를 **1개 엑셀 파일**로 통합 다운로드한다.
- **G6.** 업로드된 RAW와 결과물은 **7일 후 자동 삭제**한다 (다중 안전장치 적용).

### 2.2 비목표 (Non-goals)
- **N1.** 강서점 외 점포 동시 운영. *단, plant_shipping_map 테이블·잡 스키마는 멀티 플랜트 확장 가능하게 설계 (부록 E 참조).*
- **N2.** SAP 직접 연동 (RAW는 항상 사용자가 업로드).
- **N3.** **역할 분리·세분 권한 관리는 비목표.** 인증 자체는 M6에서 이메일 OTP로 도입.
- **N4.** 모바일 최적화 (PC + 프린터 환경 가정).
- **N5.** 출력 양식(컬럼 순서·시트 구조) 변경 기능.
- **N6.** **성능 보장 비목표**: 한 RAW 10,000행 권장, 50,000행 초과는 거부. 한 RAW 50MB 초과 거부.
- **N7.** **백업 / 7일 이후 복구는 비목표**. 7일 자동 삭제 후 재출력 요청 거절.

## 3. 시나리오
1. 강서점 운영 담당자가 SAP에서 1·2·3·4단계 RAW 엑셀을 각각 내려받는다.
2. 웹서비스에 접속해 4개 슬롯에 4개 파일을 드래그&드롭 (파일명·시트명 무관).
3. 서버가 각 파일의 헤더를 NFKC 정규화 후 시그니처 매칭으로 1~4단계 슬롯에 자동 배정. 실패 시 드롭다운으로 수동 지정.
4. 자동 처리 결과 미리보기(출력1·2·3 + ETC 리포트 + 경고 로그) 화면에서 사용자가 검수. 잡 메타에 자동 저장 → 잡 URL 공유 시 동일 상태로 재진입 가능.
5. 사용자가 SAP에 1·2단계 RAW를 등록하러 **외부 이탈** → PG번호를 받아 와 화면의 PG 입력란에 기입. 입력값은 blur 시 자동 저장 → 다음 날 같은 URL로 재진입해도 복원.
6. 시스템이 **플랜트별 PG 일관성 검증**(다르면 오류 팝업). PG 정규식 `^\d{10}$` 검증. 통과 시 인쇄 미리보기 진입.
7. ETC 리포트가 0건이 아니면 **"ETC N건 확인함" 체크박스**를 강제. 미체크 시 인쇄 버튼 비활성.
8. 인쇄 미리보기에서 머리글(문서명·출고요청일) 인라인 수정. "인쇄" 클릭 → `window.print()`.
9. "통합 엑셀 다운로드" 클릭 → `{출고지명}_데일리 작업지시서_{YYYYMMDD}.xlsx` (시트 8개 = RAW1~4 + 출력1·2·3 + ETC 리포트).
10. 7일 후 Vercel Cron + 보조 정리 로직이 Neon 행과 Vercel Blob 객체를 삭제.

## 4. 요구사항

### 4.1 F1 — RAW 4종 업로드 + 자동 판별
- **F1.1** 업로드 슬롯 4개. 형식 `.xlsx`/`.XLSX` 허용. `.xls`/`.xlsm` 거부. 단일 RAW 50MB 초과 거부.
- **F1.2** 헤더 시그니처(컬럼 헤더 문자열 기준, NFKC 정규화 + 공백·특수문자 제거 후 substring 매칭):
  - **1단계**: 헤더에 `{구매 그룹, Plnt, 합계, 오리지날 브랜드명, 자재}` 동시 포함 + Y열 헤더 == '합계'
  - **2단계**: 헤더에 `{분배번호, 분배 지정일, 점포명, BOX수량, 납품가능수량}` 동시 포함
  - **3단계**: 헤더에 `{PG No., WO, WT, 소스 빈, 자재그룹명, 피킹 수량}` 동시 포함
  - **4단계**: 헤더에 `{상품코드, EAN코드, 입수수량, 자재 그룹, 효력 시작일}` 동시 포함
- **F1.3** 매칭 실패 시 단계 드롭다운 노출 (옵션 1~4단계, **이미 점유된 단계는 비활성**, 유사도 % 힌트 표시). 동일 단계가 2개 이상 매칭되면 마지막 업로드 우선 + 경고. 4 슬롯 미완 시 '다음' 버튼 비활성.
- **F1.4** `티코드` 등 무관 시트 무시. 4단계는 시트 1개 가정.
- **F1.5** RAW는 1~10,000행, 20개 내외 컬럼 가정. **N6 비목표 참조**.
- **F1.6** 통합 1개 파일(첨부 샘플처럼 8개 시트 한 파일)도 허용 — 시트별로 1~4단계 자동 분리. 통합과 개별 RAW 혼합 업로드 시 마지막 업로드 우선.
- **F1.7** 이미 인식된 슬롯에 다른 파일 드롭 시 "덮어쓰기 확인" 모달.
- **F1.8** 미리보기 진입 후에도 RAW 1개만 교체해 부분 재처리 지원. 단, 교체 시 입력된 PG·인라인 편집값은 dirty 무효화 확인 모달.

### 4.2 F2 — 출력1 「관리용 문서」 생성
- 헤더 그대로: `구매그룹 | 플랜트 | 출고지 | 수량 | 납품번호 | PG번호 | 브랜드`
- 행 단위: 1단계에서 **(납품번호, 구매그룹, 플랜트, 브랜드) 그룹별 1행**, `수량 = SUM(1단계.Y열)`. **그룹키 4개 모두 표시 컬럼.** 한 납품번호 안에 여러 구매그룹·브랜드가 있으면 각각 별도 행으로 분리.
- 출고지: `plant_shipping_map` 테이블 lookup. `8227 → "강서"` (현재 1행, 부록 E 참조).
- **브랜드 정제 규칙** (전각 괄호·다중 공백 대응):
  ```python
  s = re.sub(r'\s*[(（][^)）]*[)）]\s*', ' ', s)
  s = re.sub(r'\s+', ' ', s).strip()
  ```
  예: `로씨로씨(ROCCI ROCCI)` → `로씨로씨`, `리오벨 (LIOBELL)` → `리오벨`, `LF종합관` → `LF종합관`, `리바이스` → `리바이스`.
- PG번호: F7에서 채움.

### 4.3 F3 — 출력3 「파렛트」 생성
- 헤더: `브랜드 | 소스빈`
- 데이터: 3단계 K열 분리 후 `(브랜드, 새 소스빈)` 쌍을 **중복 제거** → 새 소스빈 **오름차순**.
- **소스빈 분리 규칙(확정)**:
  - `new_sourcebin = K[0:9]` (첫 9문자)
  - `box_no = K[K.rfind('-')+1:]` (마지막 하이픈 뒤, 가변 길이)
  - 실측: 샘플 K열 188행 분포 `{len 11:7, 12:27, 13:109, 14:45}`, 모든 행에서 `K[9]=='-' && rfind('-')==9` → 규칙 100% 안전.
- **검증**: `len(K) < 11` 이거나 `K[9] != '-'` 이면 경고 로그 + 출력 제외 + 사용자 알림.
- 브랜드: 자재코드(=3단계 E열)로 1단계 Q열 lookup 후 F2와 동일한 정제 규칙 적용.
- 상단 머리글 셀(R1A1): `{출고지명}_데일리 출고일 : YYYY.MM.DD` (오늘, 사용자 변경 가능).

### 4.4 F4 — 출력2 「피킹지시서」 생성
- 헤더 그대로: `브랜드 | 소스빈 | 박스번호 | 자재코드 | EAN | 자재그룹 | 자재그룹명 | 피킹수량 | 미피킹수량 | 비고 | 복종 | 아이템`
- **데이터 분리 키 (확정)**: **(자재코드, 새 소스빈, 박스번호)**. 같은 자재코드·소스빈이라도 박스번호가 다르면 별도 행. → 사용자 결정.
- **매핑 (부록 A 정식 표 참조)**:
  - 소스빈/박스번호 ← 3단계 K열 분리값 (자재코드+행 단위)
  - **EAN ← 4단계에서 자재코드 == A열(상품코드)인 행 중**:
    1. `EAN코드 == 상품코드` 인 행 우선
    2. 없으면 첫 행
    3. 매칭 0건이면 빈칸 + 경고
  - 자재그룹/자재그룹명 ← 3단계 R/S열 (행별 원본)
  - **피킹수량 ← 3단계 G열(행별 원본)을 그대로 사용**. *실측: SUM(1단계.Y) == SUM(3단계.G) == 415, 자재코드별 합계도 170개 모두 일치 → 분배 로직 불필요, 합계 자동 보존.*
  - 브랜드 ← 1단계 정제값 (자재코드 lookup)
  - **복종** ← `자재그룹[1]` (왼쪽 2번째 1글자). 결과는 `{W, M}` 화이트리스트로 검증. 외 값은 ETC 리포트로.
  - **아이템** ← `자재그룹[-2:]` (마지막 2글자). 자재그룹 길이 3 이하면 ETC 리포트.
  - 미피킹수량/비고 → 빈칸(현장 수기)

### 4.5 F5 — 인쇄용 페이지 분할 (출력2 기반)
- **페이지 = (복종) × (아이템) × (그룹)**
- 그룹 정의: `ABC = {A,B,C}` / `DF = {D,F}`. **E·G~Z 등 그 외 글자는 모두 ETC 리포트로 분리**, 인쇄 페이지 미포함.
- 그룹 정의는 `config/groups.json`으로 **외부화** (코드 수정 없이 변경 가능).
- 페이지 내 정렬: 소스빈 **오름차순**.
- 빈 그룹은 페이지 미생성.
- **그룹의 행 수가 한 페이지 행 수(약 25행) 초과 시 다중 페이지 분할**: 페이지 머리글 `현재/전체`에 `2/3` 같이 표기, 표 헤더(`thead`) 매 페이지 반복.
- 인쇄 영역은 **범위를 `A1:..{마지막행}`처럼 한정** (VBA 함정: 열 전체 지정 시 머리글 깨짐 회피).
- A4 세로. 여백 통일: `@page { size: A4 portrait; margin: 8mm 3mm; }` **(F8과 일치)**, 일부 레이저프린터의 비인쇄 영역(통상 4~5mm)에 가려질 수 있어 인쇄 검증 시 안전 마진 5mm 권장 (부록 D).
- 컬럼: 출력 시 **복종·비고 숨김** → 표시 10컬럼(브랜드 ~ 미피킹수량). 폭 비율 부록 D 참조.
- 행 높이: 8mm (현장 가독성).

### 4.6 F6 — 머리글 / 바닥글 (정량 사양은 부록 D)
- **머리글 (총높이 약 22mm, 3행 그리드)**:
  - **1행 중앙**: `YYYY-MM-DD/HH:MM AM/PM` — `window.print()` 호출 직전 시각. 재인쇄 시 갱신.
  - **2행 좌**: 문서명(편집 가능, 기본값 `피킹지시서 - 강서점 데일리 필업(O구매그룹)`. 'O구매그룹'의 'O'는 **문자 O 하드코딩**, 사용자가 머리글 인라인 편집으로 자유 변경)
  - **2행 우**: `작업자 :` (수기용 빈칸)
  - **3행 좌**: `출고요청일 : YYYY.MM.DD` (편집 가능)
  - **3행 중**: `PG번호 : {pg}` (F7에서 입력된 값)
  - **3행 우**: `피킹 총수량 : {해당 페이지 출력2 행의 피킹수량 합계}`
- **바닥글**:
  - 좌: `MMDD_강서점 데일리 필업_O구매그룹` (오늘 MMDD, 출고지명·구매그룹 토큰은 머리글과 동일하게 편집 가능)
  - 우: `{현재페이지} / {전체페이지수}`
- 머리글/바닥글 편집은 **전체 페이지 일괄**, 자동 저장 + undo 1회 + "기본값 복원" 버튼. 빈 문자열·과거 출고요청일은 경고.

### 4.7 F7 — PG번호 입력 단계
- 자동 처리/미리보기 후 **별도 "PG번호 입력" 단계**.
- 화면: **감지된 플랜트 목록**(현재는 8227 강서 1개)에 각각 입력란.
- **PG 정규식**: `^\d{10}$` (10자리 숫자). masked input + blur 시 검증. 불일치 시 입력란 빨강 + 에러 메시지. 미통과 시 '다음' 버튼 비활성.
- **플랜트별 일관성**: 같은 세션에서 동일 플랜트에 서로 다른 PG가 들어오면 오류 팝업 + 진행 차단.
- **이탈/재진입/뒤로가기**:
  - blur 시점에 잡 메타에 자동 저장.
  - 동일 잡 URL 재진입 시(다음날·다른 PC) 입력값 복원.
  - '뒤로(미리보기)' 클릭 시 PG 값 보존, dirty 상태 유지.
  - 미리보기에서 RAW 교체 시 "PG·인라인 편집값을 무효화하시겠습니까?" 모달 → 동의해야 진행.
  - PG는 인쇄 미리보기에서도 재수정 가능. 출력1·머리글·통합 엑셀 모두 즉시 갱신.
- **동시 편집**: 같은 잡 ID에 두 사용자가 동시에 PG 입력 시 last-write-wins. 다른 세션 새로고침 시 경고 토스트.

### 4.10 F10 — DB 7일 자동 삭제 (다중 안전장치)
- Neon 스키마(Drizzle ORM, 멱등 마이그레이션):
  ```sql
  -- 멱등 (IF NOT EXISTS), 하위호환 (NOT NULL 컬럼은 default 부여)
  CREATE TABLE IF NOT EXISTS plants (
    plnt TEXT PRIMARY KEY,
    outlet_name TEXT NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
  );
  CREATE TABLE IF NOT EXISTS jobs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),   -- 예측 불가
    plnt TEXT NOT NULL REFERENCES plants(plnt),
    status TEXT NOT NULL DEFAULT 'uploaded',
    source_filenames TEXT[] NOT NULL DEFAULT '{}',
    blob_keys TEXT[] NOT NULL DEFAULT '{}',
    pg_numbers JSONB NOT NULL DEFAULT '{}',          -- {plnt: pg}
    header_overrides JSONB NOT NULL DEFAULT '{}',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at TIMESTAMPTZ NOT NULL DEFAULT (now() + interval '7 days'),
    created_by_email TEXT                            -- M6 이후 채움
  );
  CREATE INDEX IF NOT EXISTS jobs_expires_at_idx ON jobs(expires_at);
  CREATE TABLE IF NOT EXISTS cleanup_log (
    id BIGSERIAL PRIMARY KEY,
    ran_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_rows INT NOT NULL,
    deleted_blobs INT NOT NULL,
    errors JSONB NOT NULL DEFAULT '[]'
  );
  ```
- 원본 RAW + 통합 엑셀 결과는 **Vercel Blob (random suffix)**에 저장. blob key prefix에 잡 ID 포함.
- **다중 안전장치**:
  1. **Vercel Cron** `/api/cron/cleanup` 매일 03:00 KST. `Authorization: Bearer ${CRON_SECRET}` 검증 필수, 미일치 시 401.
  2. 업로드 핸들러가 best-effort로 `expires_at < now()` 행을 batch 정리 (cron 단일 실패점 완화).
  3. cron 실행 결과를 `cleanup_log`에 기록, **최근 24h 동안 row 없으면 알람** (Slack webhook 또는 Sentry).
  4. **고아 Blob 검증 잡 주 1회**: DB에 없는 Blob 객체 삭제.
- `cleanup_log`에도 30일 TTL 적용 (별도 cron).

## 5. UX (화면 흐름)
```
       ┌─────────────────────────────────────────────────┐
       │  ① 업로드  ↔  ② 미리보기  ↔  ③ PG 입력  ↔  ④ 인쇄/다운로드
       └─────────────────────────────────────────────────┘
             ↑ dirty 상태 시 확인 모달
```
1. **메인** — 좌측 진행 단계 4개 표시.
2. **업로드** — 4개 슬롯 카드. 슬롯별 자동 판별 결과 배지 + 유사도 %. 매칭 실패 시 드롭다운(이미 점유된 단계 비활성). 덮어쓰기 모달.
3. **처리 미리보기** — 탭: `[출력1]` `[출력2]` `[출력3]` `[ETC 리포트]` `[경고 로그]`. KPI(행 수, 페이지 수, 자재코드 수, 합계 검증 결과). 잡 URL 공유 가능.
4. **PG 입력** — 플랜트별 입력란 + masked input + 검증 메시지. blur 시 자동 저장.
5. **인쇄 미리보기** — 머리글 인라인 편집, 페이지 네비, ETC 0건 아니면 확인 체크박스 강제. 인쇄 버튼.
6. **다운로드** — "통합 엑셀 다운로드" 토스트.
- 모든 단계 사이 양방향 이동 가능. 뒤로가기 시 dirty 상태 유지.

## 6. 엣지케이스
- **E1.** K열 9번째 문자가 하이픈이 아닌 경우 → 경고 로그 + 출력 제외 + 사용자 알림.
- **E2.** 자재그룹이 3글자 이하 → 복종/아이템 추출 실패 → ETC 리포트로 분리.
- **E3.** 자재코드가 1단계에는 있으나 3단계에 없음 → 출력2에 행 없음 + 경고.
- **E4.** 자재코드가 4단계에 없음 → EAN 빈칸 + 경고.
- **E5.** 한 자재코드가 3단계에 여러 (소스빈, 박스번호) 조합 → 각각 별도 행 (분리 키 확정).
- **E6.** 한 납품번호에 여러 브랜드 → 출력1에서 브랜드별로 행 분리.
- **E7.** 1단계 Plnt가 8227 이외 값 포함 → 처리는 하되 출력1 출고지를 "미정"으로 두고 경고.
- **E8.** 머리글 'O구매그룹' 토큰은 하드코딩 + 사용자 자유 편집.
- **E9.** PG번호가 정규식 `^\d{10}$`에 맞지 않음 → 입력 거부 (masked input + blur 검증).
- **E10.** 헤더 시그니처 매칭이 두 단계에 모두 걸림 → 사용자 수동 지정.
- **E11.** 동일 시점에 두 사용자가 업로드 → 잡 ID(UUID) 격리, 결과물 충돌 없음.
- **E12.** 잡 URL 재진입(다음날·다른 PC) → 입력값·미리보기 상태 복원.
- **E13.** 미리보기에서 RAW 1개 교체 → "PG·편집값 무효화" 모달 강제.
- **E14.** 이미 인식된 슬롯에 다른 파일 드롭 → "덮어쓰기" 모달.
- **E15.** 같은 잡 ID 동시 편집 → last-write-wins + 다른 세션에 경고 토스트.
- **E16.** 엑셀 셀이 수식(formula) → `data_only=True`로 로드해 계산값 사용. None이면 빈 셀로 처리.
- **E17.** RAW에 병합 셀 포함 → 첫 셀에만 값 할당, 나머지는 빈 셀 처리.
- **E18.** 같은 잡 ID에 두 번 "처리 시작" → 멱등 처리(잡 ID + 입력 해시로 중복 실행 차단).
- **E19.** 시트명·헤더에 인코딩 깨짐(모지바케) → NFKC 정규화 + 공백·특수문자 제거 후 substring 매칭으로 회피.

## 7. 성공기준 (Acceptance Criteria — 검증 가능)
- **AC1.** 첨부 샘플 1개 파일(8시트)을 업로드해 **경고 0건, 출력1/2/3 행 수 > 0, AC3·AC4·AC5·AC6·AC12 통과**.
- **AC2.** 4단계 RAW를 각각 별도 파일로 업로드 + 시트명·파일명이 영문/변형이어도 자동 판별 성공 (NFKC 정규화 적용).
- **AC3.** `SUM(출력1.수량) == SUM(1단계.Y열)` (검증 로그).
- **AC4.** 출력3 행 수 == `(자재코드, 새 소스빈) distinct` 개수.
- **AC5.** 출력2의 각 행 (브랜드/소스빈/박스번호/자재그룹/자재그룹명/EAN/피킹수량/복종/아이템)이 부록 A 매핑대로 채워짐. 분리 키 = (자재코드, 새 소스빈, 박스번호) distinct.
- **AC6.** 인쇄 미리보기 페이지 수 == `Σ(복종×아이템×{ABC,DF}) 중 빈 그룹 제외 + 다중 페이지 분할`.
- **AC7.** Playwright headless PDF 렌더링 시 가로 스크롤 0px, 컬럼 폭 비율은 **부록 D**의 표 ±2% 이내. 폰트 8pt 고정.
- **AC8.** 통합 엑셀을 다시 업로드 → 출력1/2/3 시트의 행 수+열별 합계+정렬 키가 동일 (시각·다운로드 메타 컬럼 제외).
- **AC9.** 시각 조작 테스트 + cron 의도적 1회 실패 시뮬레이션 시, 다음 정리에서 누적 잔여 0건 (DB row + Blob 객체 모두).
- **AC10.** PG번호가 플랜트별로 일관하지 않거나 `^\d{10}$` 위반 시 다음 단계 진입 차단.
- **AC11.** E·G~Z 등으로 시작하는 소스빈은 인쇄 페이지 제외, ETC 리포트 카드 + 통합 엑셀 ETC 리포트 시트 모두 노출. ETC 0건 아닐 시 "ETC N건 확인함" 체크박스 강제.
- **AC12.** `SUM(출력2.피킹수량) == SUM(1단계.Y열) == SUM(3단계.G열)` (실측: 415).
- **AC13.** M6 후 미인증 다운로드 요청 → 403.
- **AC14.** `CRON_SECRET` 없는/잘못된 `/api/cron/cleanup` 호출 → 401.
- **AC15.** 잡 ID A의 다운로드 URL로 잡 ID B 파일 접근 시 403.
- **AC16.** 단일 파일 50MB 초과 / 총 업로드 100MB 초과 거부 (413 + 사용자 메시지).
- **AC17.** 같은 잡 ID에 동시 PG 입력 시 last-write-wins, 다른 세션 새로고침 시 경고 토스트.
- **AC18.** 합성 fixture로 E빈·짧은 자재그룹(3글자 이하)·다중 EAN·다중 (자재코드, 소스빈, 박스) 케이스를 단위테스트로 검증 (샘플 데이터에 자연 발생 0건 케이스 회귀 보장).
- **AC19.** GitHub Actions에서 lint·typecheck·unit test가 모두 통과 (출력1·2·3 생성 함수, 소스빈 분리 함수, 브랜드 정제 함수, EAN 다중매칭 함수 단위테스트 포함).

## 부록 E — 멀티 플랜트 확장 호환성 메모

```sql
-- plants 테이블 분리 (점포 추가 시 row 1개만 insert)
INSERT INTO plants(plnt, outlet_name) VALUES
  ('8227', '강서'),
  -- 추후: ('XXXX', '점포명') ...
  ON CONFLICT (plnt) DO NOTHING;
```

- `jobs.plnt` → `plants.plnt` FK.
- 한 잡(`jobs.id`)은 현재 단일 plnt 가정. 멀티 플랜트 잡(여러 plnt 동시) 케이스는 M7에서 `jobs.plnt`를 `TEXT[]`로 마이그레이션 + PG 입력 UI 다중 플랜트 지원.
- `outlet_name`은 출력1·머리글·파일명에 사용. 변경 시 plants row 업데이트만으로 모든 출력 반영.
- 사용자가 추후 제공할 점포 목록은 `db/seed/plants.sql`로 일괄 적용.
